# tldraw/Yjs v3：稳定记录与存在意图

用户于 2026-11-07 确认实现。保留 Yjs/Liveblocks/IndexedDB，压缩、历史容量与物理回收后续独立处理。

- 共享根 `tl_records_v3` 保存稳定的记录/props Map，`keep` 布尔值表示显式存在，解码到 TLRecord 时移除控制字段。
- 有效画布由 keep=true 的记录及其传递依赖组成：shape 的父级和资源、binding 的端点。依赖缺失、非法类型和父级环仍报错；不会根据本地旧视图修补共享状态。
- 新建先以非历史 origin 物化 keep=false 的不可见 payload，再在用户事务中激活。新增 payload 不进入 UndoManager；字段修改与激活/关闭进入同一个用户操作历史。
- 删除关闭 keep，保留 payload；不重建原有共享子树，不生成补偿事务。
- 已接收冲突继续整步拒绝。撤销模拟中，若将显式存在记录关闭后仍被已知有效依赖需要，也拒绝，不能用投影掩盖已知冲突。
- 未接收子元素在撤销后到达，则保全其必要祖先。同一步中不相关的对象维持撤销结果，用户已明确选择此规则。
- 父容器仅因依赖保留时提供提示；最后一个有效依赖移除后，若原容器 keep 仍为 false，它也隐藏。
- 历史与远端计数仍为会话内状态。刷新或只读新端仅依赖持久化共享状态计算同一有效图。
- 新房间使用 v3。v1/v2 在线只读并提供备份，不自动迁移；本地明确升级、离线转换保留旧根与精确基线。协议准入拒绝旧客户端进入 v3 房间，但不能撤销既有 token，线上升级仍需旧写入者隔离。
- 所有初始加载、同步、撤销模拟和 AI 正式应用都通过同一状态读取与图校验。
- 不声称解决任意关系冲突：并发 reparent 成环仍进入错误/备份路径。隐藏记录和历史的保留开销本次不回收。

证据起点：原实现 9 类场景×3轮，18 次缺父复现、6 次正常对照、3 次单端补偿原型；另20次低层实验确认多端重建同 ID 父树会覆盖独立字段。此记录不等于 v3 验收通过。

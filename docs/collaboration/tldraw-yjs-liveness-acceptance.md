# v3 存在意图验收记录

2026-11-07，方案 A 隔离工作区，基于 `c7f810a`。本次实现不做压缩、历史限额或物理回收，没有合并、推送或云端迁移。

## 实现结果

- `tl_records_v3` 保留稳定 payload；`keep` 表示显式存在，原生 TLRecord 不含控制字段。
- 非历史 origin 物化不可见 payload；用户历史记录激活、字段变化及逻辑关闭，不删除共享树。
- 有效图包括显式存在对象及其传递依赖。迟到子元素保留父链，同一步无关对象保持撤销结果；最后依赖移除后，逻辑关闭的祖先隐藏。
- 已收到的字段/引用冲突继续整步拒绝；撤销副本检查显式关闭对象是否仍被已知依赖需要。
- 字段自身的 existence 版本与引用目标的 root 身份版本分离：父级逻辑关闭不等于树身份变化，不应阻止子元素作者撤销自己的创建。
- v1/v2 旧根与精确基线保留；线上旧格式只读，新房间协议3，本地升级必须显式执行。旧根晚写、元数据降级、v3根记录被删除/替换均暂停编辑并保留备份路径。
- 原生历史计数桥接继续使用，增加引用保留提示；本地复用现有 flex 布局，避免提示挤出画布。

## 真实浏览器

Chrome，实际 tldraw Editor、生产 binding/history/notice、独立 Y.Doc 与独立 IndexedDB 名称；两个 iframe 客户端通过可控本机持久化HTTP中继上传/拉取，模拟跨设备更新延迟。临时页面用 Next 16.2.1 production build，编译及自身 TypeScript 检查通过；不运行项目的 Prisma build 前置脚本。

9类×3轮，共27个v3场景全部通过：

1. 已收到子元素时，父创建撤销整步拒绝。
2. 未收到子元素即撤销，A先接收时保全父子。
3. 同一并发，B先接收时同样保全父子。
4. 子元素作者上传后关闭，新客户端仍可从中继加载合法父子结构、历史为空。
5. 实际IndexedDB保存并销毁/重建客户端后，父子合法、历史为空，父keep仍为false。
6. 并发后重做恢复父容器显式存在，父子保持合法。
7. 对方快照乱序与重复投递，不触发错误或额外修复写入。
8. A移动/B改色，A撤销保留红色，位置回到80。
9. B撤销最后一个子元素后，父子均隐藏，原父payload仍保留且无修复写入。

另实际点击原生工具栏：A撤销父创建后收到迟到子内容，父子重新显示并出现保留提示；B原生撤销自己的子创建后父子隐藏；B原生重做后恢复父子。最终两端error=null、parentKeep=false、retained=1、repairWrites=0。

原始结构化证据见 [browser results](evidence/2026-11-07-liveness-browser.json)。完整临时页面源代码及每次中继二进制快照保留在本聊天产物目录 `liveness-browser`；这些故意构造的测试房间与真实业务房间隔离。
